# v0.1.0 — release draft

Status: prepared for review; no project release or tag has been published.

## Release notes

The first tagged release focuses on predictable runner setup and cleanup on
Linux/systemd. Missing or invalid repository lists stop synchronization before
removal, installation errors propagate, and failed deregistration preserves
local runner state. Repository lists support comments, CRLF, duplicates, and a
final line without a newline.

Installation verifies the official runner archive checksum, uses the correct x64
asset name (including amd64 aliases), and starts the service through `runsvc.sh`.
Cleanup discovers stopped runners and repositories no longer in the desired list.
Ownership checks prevent changes to another account's services.

The bootstrap GitHub Runner version is 2.337.0; it is separate from project
version v0.1.0. GitHub's default runner automatic updates remain enabled.

## Upgrade notes

- Existing `owner_repo` directory and service names remain supported.
- Remove the unused `REPO_OWNER` setting if desired.
- For a custom `RUNNER_VERSION`, also set its official `RUNNER_SHA256`.
- Review `repos.txt` before `sync.sh`: an explicitly empty valid list removes all
  managed runners belonging to the current account.
- Run `register_all.sh` to refresh existing service entry points.
- Workflows must be trusted. Jobs share the installing user's permissions;
  directory separation provides no security isolation.
